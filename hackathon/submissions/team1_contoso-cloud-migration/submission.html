The Problem

Contoso Financial — 3 On-Prem Workloads

  • Portal — .NET 4.7 / IIS / Windows Server 2016
  • Recon — Python cron job, 2am nightly, 47-min runtime
  • ReportDB — SQL Server 2017, 5 teams query directly

CFO signed the cloud contract. CTO wants cloud-native. They disagree. Clock is running.

The Decision (ADR-001)

Lift-and-shift first. Optimize in Phase 2.

Refactor-on-the-way-in was rejected. Discovery (ADR-002) found three undocumented dependencies that would have broken a naive migration. With unknown blast radius, the only safe play is a tested baseline in cloud before changing anything.

Phase 1: 45-day cutover Phase 2: day 60+ CFO wins CTO wins

Discovery Findings — The Things Nobody Documented (ADR-002)

FinSecLib.dll — UNC Lock File PCI tokenisation binary (no source, no vendor) writes lock files to \\fileserver01\finlib-locks\. Silent failure if share is unavailable. Not in any arch doc.
Ghost VM — 172.16.4.42 Decommissioned VM, still running, called by Recon on every job. # TODO: remove after Dec 2022 never removed. Response usage unclear.
ReportDB Linked Server SQL Server linked server to external credit bureau creditcheck.ext.contoso.com:1433. Runs daily via SQL Agent job. Cannot be replicated in RDS.
